# 자동 발행 재개 체크리스트

2026-08-30 에 매일 자동 발행을 중단했다. 이 문서는 **언제, 어떤 조건에서** 다시 켜는지를 적어 둔 것이다.

## 왜 멈췄나

애드센스가 두 번 거절했다. 두 번 다 사유가 같았다 — "가치가 별로 없는 콘텐츠".
1차 거절 후 79편 → 88편으로 늘리고 글자수를 채웠지만 판정은 그대로였다.

진단해 보니 원인은 편수도 분량도 아니었다.

**초안을 쓰는 `content-writer` 에이전트가 WebSearch·WebFetch 를 갖고 있지 않았다.**
88편 전부를 쓴 작가가 외부 자료를 단 한 번도 열어본 적이 없다는 뜻이다.
발행 게이트 5개(check-topic, check-duplication, count-body, verify-anchors, verify-faq-match)도
전부 자기 사이트 내부만 검사했다 — "웹에 이미 있는 답 대비 이 글이 무엇을 더하는가"를
묻는 검사가 파이프라인 어디에도 없었다.

그 결과가 실측으로 이렇게 남았다.

| 항목 | 88편 기준 |
|---|---|
| 외부 출처를 인용한 글 | 7편 |
| 이미지가 0장인 글 | 70편 |
| 1인칭 경험 서술 | 0건 |
| 국내 상품·브랜드 고유명사 | 0건 |
| 개인 저자 표기 | 0건 (전부 `@type: Organization`) |
| 판단 회피 표현 | 307회 (편당 3.5회) |

구글은 2026-07-25 이후 새 글을 **크롤링조차 하지 않는다.**
GSC "발견됨 - 현재 색인이 생성되지 않음" 22건, 전부 최종 크롤링 "해당사항 없음".
7주간 검색 클릭 총 13회. 애드센스의 판정과 구글봇의 크롤링 포기는 같은 원인의 두 얼굴이다.

이 상태로 계속 돌리면 크롤링되지 않는 페이지만 하루 한 장씩 쌓인다.

## 왜 "고쳤으니 바로 재개"가 아닌가

이미 한 번 그렇게 했다가 실패했다.

7/27 커밋 `51e58d7` "애드센스 판정 대응 — 전면 개선"(75파일, +4,900줄)이 글 5편에
손으로 참고자료를 붙였다. 그런데 `post-template.html` 에도 `publish-reviewer.md` 에도
출처 요구를 넣지 않았다. 커밋 메시지의 '재발 방지' 항목에 출처가 아예 없다.

**이후 발행된 37편 중 35편이 무출처로 회귀했다.** 건강 카테고리만 보면 15편 중 14편(93%).

교훈은 하나다 — **파이프라인에 박지 않은 개선은 예외 없이 사라진다.**
그래서 이번엔 산문 규칙이 아니라 스크립트로 강제한다.

## 재개 전 확인 (전부 체크돼야 함)

### 1. 파이프라인 개조가 끝났는가

- [ ] `.claude/agents/content-writer.md` frontmatter 에 `WebSearch, WebFetch` 있음
- [ ] `.github/scripts/daily-draft.sh` 의 `--allowedTools` 에 `WebSearch` `WebFetch` 있음
      (frontmatter 선언만으로는 실행 시 부여되지 않는다 — keyword-researcher 가
       WebSearch 를 선언해놓고도 못 쓴 것이 정확히 이 이유였다)
- [ ] `scripts/verify-sources.mjs` 가 있고, 출처 2개 미만이면 exit 1 한다
- [ ] `scripts/check-external-novelty.mjs` 가 있고, NOVELTY 3건 미만이면 exit 1 한다
- [ ] `publish-reviewer.md` 차단 기준에 6-2(외부 근거)·6-3(차별화)·6-4(판단 회피)가 있음
- [ ] `post-template.html` 에 NOVELTY 블록·`📚 참고한 자료`·`<figure>` 슬롯이 있음
- [ ] `keyword-researcher.md` 의 "초보 필수 커리큘럼 27슬롯"이 제거돼 있음

### 2. 새 게이트가 실제로 작동하는가

- [ ] 새 규칙으로 쓴 글 **5편**을 사람이 직접 읽었다
- [ ] 그 5편 각각에 대해 "이 글에 웹에 없던 게 정말 있는가"에 예라고 답할 수 있다
      (NOVELTY 블록에 적힌 3개를 실제로 검색해 봤다는 뜻이다. 스크립트 통과로 갈음하지 마라 —
       이 항목만은 기계가 최종 판정을 못 한다)
- [ ] 그 5편의 참고 자료 링크를 **직접 클릭해서** 살아 있고 주제와 맞는지 확인했다
      (환각 링크는 출처가 없는 것보다 나쁘다)

### 3. 구글이 다시 보고 있는가 — 이게 가장 중요하다

- [ ] GSC "발견됨 - 현재 색인이 생성되지 않음"이 22건에서 **10건 이하**로 줄었다
- [ ] 재작업·신규 발행한 글의 "최종 크롤링"에 **실제 날짜가 찍혔다**
      ("해당사항 없음"이 아니라)
- [ ] 검색 노출(클릭 아님)이 7/22 이전 수준 이상으로 회복됐다

**3번이 안 채워졌으면 재개하지 마라.** 구글봇이 크롤링하지 않는 페이지는
애드센스 심사에서도 평가받지 못한다. 글을 더 써도 아무 일도 일어나지 않는다.

## 재개하는 법

세 묶음이 전부 체크됐으면:

1. `.github/workflows/daily-draft.yml` 의 `schedule:` 블록 주석을 푼다.
   **단, cron 을 주 2회로 바꾼다.** 예: `0 0 * * 2,5` (화·금 09:00 KST)
2. `.github/scripts/draft-watchdog.sh` 의 `PAUSED=${PAUSED:-1}` 을 `PAUSED=${PAUSED:-0}` 으로.
   (이걸 안 바꾸면 발행 실패해도 감시가 알리지 않는다)
3. 감시의 "오늘 초안 없음" 판정도 주 2회 기준으로 맞춰야 한다 —
   지금 로직은 매일 발행을 전제한다. 화·금이 아닌 날을 정상으로 봐야 한다.

**매일로는 돌아가지 않는다.** 하루 한 편을 새 게이트 통과 품질로 만드는 것은 불가능하고,
불가능한 목표는 게이트를 우회하게 만든다. 커리큘럼 빈칸 채우기가 정확히 그렇게 생겨났다.

## 재개해도 되지만 애드센스 재신청은 별개다

재신청 조건은 위 3번 세 항목 **전부** + 신규·재작업 글 20편 이상이 실제로 색인된 것.
실질 변화 없이 넣는 3차 신청은 같은 사유로 거절되고 패턴만 남긴다.
기다리는 비용보다 3차 거절의 비용이 크다.
